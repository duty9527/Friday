# F.R.I.D.A.Y. Web 控制台信息架构与原语规范

本文档定义 F.R.I.D.A.Y. Web 指挥台的顶层概念分层与新增功能归位约束，防止随着插件、定时任务与观测能力增加出现顶栏和导航概念膨胀。

## 一、三层架构：1 主舞台 + 4 恒定原语 + 1 系统底座

### 1. 主舞台（常驻工作面，不进顶栏菜单）

| 区域 | 定位 | 承载内容 |
| --- | --- | --- |
| **中栏 · 持续对话** | 单一持续在线交互入口 | 主对话流、多渠道筛选、`ASK_BOSS` 盘中请示拍板区 |
| **左栏 · 任务舱（Works）** | 后台并发 Worker 队列 | 运行中与已结算的隔离任务列表及控制 |
| **右栏 · 执行链路（Activity）** | 可阅读的逐步过程与因果轨迹 | 链路时间线、语义详情检视器，以及标题栏入口 **`🧭 思考流程图`（`/mindmap`）** |

### 2. 顶栏左侧：4 个恒定「副手能力原语」（`M1 ~ M4`，永不再增 `M5+`）

| 槽位 | 原语名 | 回答的问题 | 现有与未来归属 |
| --- | --- | --- | --- |
| **`M1`** | **全息记忆** | 它**知道什么**、未来**会怎么做**？ | 三层全息记忆、3D 突触矩阵；未来扩展程序性技能剧本（Skills）与睡眠巩固视图 |
| **`M2`** | **定时与目标** | 它何时**自主干活**？ | 周期 / 单次定时器、有终态目标（`goalCondition` + 自动/手动达成停机）、连续失败疲劳熔断（首错通知、中间静默、达阈值停机）、对话创建护栏（20 活跃上限 + 最小周期限制）及左侧任务舱 `initiator` 定时来源标识 |
| **`M3`** | **应用与插件** | 它的**手能伸到哪**？ | 统一的插件目录 + 已启用插件的专属交互看板宿主（如 `health-scale` 健康管理、`fund-tracker` 投资管理），全部通过 `PluginSurfaceRegistration` 按需懒加载 |
| **`M4`** | **IM 与声纹** | 我在**哪儿能叫到它**？ | 微信 / 钉钉 / Telegram / 小爱语音接入、CAM++ 声纹档案与角色门禁 |

### 3. 顶栏右侧：1 个「系统底座」（`SYS`，归机主的基础设施层）

位于顶栏右侧（与副手能力原语物理区隔），通过统一弹窗的 Tab 承载归机主掌控的底层设施与账本：

- **🧩 模型与提供方**：异构模型池、API Key / OAuth 接入、主控与 Worker 调度路由
- **📊 用量账本**：按日 / 周 / 月全链路调用统计、Token 消耗与汇率折算费用
- *(未来预留)* **凭据保险库（Vault）** 与 **边界护栏（Approvals）**：统一托管密钥与安全红线，密钥归人而不归 AI

## 二、新增功能的归位铁律

1. **禁止在顶栏新增 `M5+` 一级按钮**：任何新功能必须归入上述三层之一，不能破坏恒定 `M1 ~ M4 + SYS` 格局。
2. **新业务插件及其专属看板一律挂载到 `M3 应用与插件`**：通过 `PluginSurfaceRegistration` 注册 Tab / Panel 与动态 `import()` 懒加载控制器，不得把具体插件硬编码进顶栏。
3. **新的执行观测与拓扑视图归入右侧「执行链路」**：如流程图、因果画布、回放视图，统一从执行链路面板进入。
4. **新的算力、凭据、预算与安全边界配置归入 `SYS 系统底座`**：与副手自身能力保持清晰的“人 vs AI”所有权边界。
